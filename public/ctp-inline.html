What changes in code

  • No schema change. Same ctp_results row per par 3: a winner, an explicit null (“no winner”), or no row (undecided).
  • One derive. eligible = !pickedUp && gross === par, run live off the draft-overlaid scores already on screen.
  • One save. A combined saveHole() queues the score cells and the CTP row through the existing outbox, one flush — durable offline, advances only if both queue.
  • Self-heals. If a score edit makes the stored winner ineligible, the pick clears and the hole flags for a re-pick.
  • Round page: read-only. Four entry cards become one glanceable list that deep-links back to Enter.

Net effect: one data-entry pass instead of two, the “must make par” rule enforced from the data itself, and a review screen that's finally just a review.
